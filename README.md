# Customer Churn Prediction for a Mobile-Money Service

Diploma capstone: an end-to-end data science project that predicts which customers are likely to stop using a mobile-money service, so the business can target retention offers.

> **Data note:** the dataset is **synthetic**, generated by `01_generate_data.py`. It imitates the kinds of fields a Kenyan mobile-money provider holds, but it is not real customer data. See `ISSUES_LOG.md`.

## Problem statement
Acquiring a customer costs far more than keeping one. Given a customer's profile and recent activity, predict the probability that they churn, and flag high-risk customers.

## Project structure
```
01_generate_data.py     create the synthetic raw dataset (with deliberate data-quality problems)
02_clean_eda_model.py   clean, explore, compare 3 models, evaluate, save the best one
03_predict.py           score new customers with the saved model
run_all.sh              runs the whole pipeline from scratch
data/                   raw_customers.csv, clean_customers.csv
models/                 churn_model.joblib
outputs/                charts and run_log.json
ISSUES_LOG.md           problems that occurred and how they were handled
```

## How to run
```
pip install pandas numpy scikit-learn matplotlib seaborn joblib
bash run_all.sh
```

## Method
1. **Data generation**: 5,000 customers plus injected duplicates, missing values, impossible values and inconsistent labels.
2. **Cleaning**: remove duplicates, standardise text labels, set impossible ages/amounts to missing.
3. **EDA**: class balance, feature distributions by outcome, correlations with churn.
4. **Split**: 80/20 stratified; all preprocessing (median/mode imputation, scaling, one-hot encoding) happens inside a pipeline to avoid leakage.
5. **Models**: Logistic Regression, Random Forest, Gradient Boosting compared by 5-fold cross-validated ROC-AUC on the training set.
6. **Evaluation**: best model scored once on the held-out test set; decision threshold chosen from out-of-fold training predictions.
7. **Explainability**: permutation importance on the raw input columns.

## Results
See `outputs/run_log.json` for the exact figures of the latest run, and the charts in `outputs/`.

## Limitations
- Synthetic data: the results show that the pipeline works, not how well churn can be predicted in the real world.
- Logistic Regression winning is a consequence of how the data was generated.
- No hyperparameter tuning or cost-sensitive threshold.
